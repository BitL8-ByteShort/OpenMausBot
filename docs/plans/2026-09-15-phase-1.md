## Why this order

The audit on Sep 15 (`docs/bench/scorecard/2026-09-15-main-vs-phase0.md` and the prompt audit in
part 1's spec) showed that per Claude call about 43,000 input tokens are Claude Code's own prompt
and ours is about 1,300; follow-up turns are served almost entirely from cache and a new thread
already reuses about 75% of the prefix. Trimming our prompt cannot move the numbers much; long
threads and recall can.

## Findings while building

- **F6 (fixtures):** the Codex fake honours `thread/resume` only in `FAKE_CODEX_MODE=resume`; in
  the default mode any second turn on a thread stalls for 30 s, on main as well. Tests that run
  more than one turn on the Codex fake must set that mode (the compaction e2e does). Worth a
  fixture fix in its own PR.
- **F7 (Claude driver, since Phase 0's F1):** the live-process reuse ignored a "start fresh"
  request (no session id), so a rewind or a compaction landed on the process that still held the
  old context. Fixed here with `SendTurnInput.sessionReset`; the other drivers already start a
  new session without a cursor.
- **F8 (summaries):** a model summary drafted by a one-shot engine call can smuggle the
  summariser's own environment (its working directory) into the record. The prompt forbids it
  and the one-shot runs in the task's folder; the deterministic record never had the problem.
- **F9 (reconciled with main):** main's commit a8751a22 added the per-task context reading
  (`usage.context.tokens`) and `model-context-window.ts` while part 1 was in progress; the branch
  now reads those and dropped its own `lastInput` and window table. A budget below the thread's
  floor (system prompt plus kept exchanges) made the harness compact every turn; the first
  post-compaction reading is now the floor and the next compaction waits for a quarter of
  regrowth (`REGROWTH_FACTOR`).
- **F10 (latency, open):** the model summary on a compaction turn costs 10–20 s (a one-shot
  Haiku call bounded at 20 s). Options for part 1b: draft the model summary in the background
  after the deterministic record is written and patch it in, or skip it below a folded size.
